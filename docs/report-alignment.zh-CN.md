# Timestral 技术报告对齐记录

依据 [Timestral 技术报告 v1](https://arxiv.org/pdf/2610.37585)，2026-10-27。
本项目继续复用固定版本的官方网络。这里区分模型已经具备的能力、社区训练层新增的机制，
以及尚未实现的后续任务；对齐某个公式不等于复现完整预训练或保证微调收益。

## 第一轮：归一化空间损失

报告 §3.3、§4.1 描述了逐 patch 推进的归一化以及模型归一化空间中的分位数损失。
本轮提供 `TrainConfig(loss_space="normalized")`；默认值仍为 `"history_scaled"`，
因此原有配置继续使用历史尺度加权的原始空间损失。

设第 j 个预测 patch 的位置和尺度为 `loc_j`、`scale_j`，则归一化目标为
`z = asinh((y - loc_j) / scale_j)`，与预测头直接输出的分位数 `q_z` 计算 pinball loss。
仅统计实际观测到且具有有效历史的目标，21 个分位数等权平均。配置关闭 `asinh` 的模型
使用相应的线性变换。

首个预测 patch 使用历史统计；后续 patch 用此前预测中位数推进统计，不能用未来真实标签
更新这些统计。预测头输出直接进入损失，不先经过原始尺度还原再反向求逆。
MPS 下神经网络保留在设备上，float64 统计在 CPU 计算，保留跨设备计算图。

报告没有公开训练时这些推进统计的完整梯度处理细节。本项目沿用原训练兼容层的选择，
保留此前预测中位数对后续统计和归一化目标的梯度；这属于实现选择，不宣称与官方训练代码完全一致。

### 验证集选择与可比性

`validation_loss_space=None` 默认沿用本次训练的 `loss_space`。
要隔离训练损失的影响，可以把两个实验的 `validation_loss_space` 都设为 `"history_scaled"`：

```python
from timestral_ft import TrainConfig

training = TrainConfig(
    mode="lora",
    loss_space="normalized",
    validation_loss_space="history_scaled",
)
```

这样两个方案使用同一种验证准则选择检查点。不同损失空间下的损失数值不应直接比较。
训练和验证目标会随配置保存；更改损失后须创建新实验，不得作为同一检查点的精确续训。
旧配置缺少这些字段时按原行为解释。

### 实验与验收

本轮实验入口、冻结协议和实测结果见 [第一轮实验记录](../results/report_round1/README.md)。
实验比较原模型、历史尺度损失和归一化损失，使用固定模型、数据划分、种子及共同选优准则。
测试只评估冻结后的方案；负结果也保留。

第一轮仅使用单预测区间训练；第二轮在其基础上新增下述 DHF 多预测块。

## 第二轮：共享历史的多预测块 DHF

报告 §3.1、图 5 中，同一条完整观测序列保留因果上下文 token，
多个连续预测块分别读取各自起点之前的上下文，以及本块内此前／当前位置的预测 token。
上下文永远不读取预测 token；相同时间位置的两种 token 共用时间编码。
本轮将该机制加入训练接口，一次 Transformer 前向共享全部上下文编码。

```python
training = TrainConfig(
    mode="lora", training_strategy="dhf", loss_space="normalized",
    validation_loss_space="history_scaled",
    context_length=256, prediction_length=192,
    dhf_min_context_patches=1, dhf_max_block_patches=6,
)
```

此处 `context_length + prediction_length` 是整条训练序列的长度预算。
在已发布模型上，448 点组成 14 个 32 点 patch，初始 1 个 patch 只作上下文，
其余 416 点均可作为每个目标的监督；默认窗口训练只监督末尾 192 点。
预测块的实际历史取决于其起点，可在 32–416 点之间变化，不能理解为固定 256 点历史。
每个样本单独采样布局，同一样本的变量共用布局，块长均匀采样自 1 到最大值，
末块截断。该均匀分布是项目选择；官方报告未披露具体块长分布。

`dhf_max_block_patches=None` 默认使用 `ceil(prediction_length / patch_size)`，
不得超过模型单块长度；初始上下文必须为正并留下真实监督位置，最长可能历史不得超出模型上限。
尾部不足一个 patch 时用缺失值右侧补齐，补齐值不参与监督。
每块的首个目标归一化框架取自其真实历史，随后仅用本块此前预测中位数推进，复用第一轮损失。
缺失标签以及起点之前没有该目标观测的块不计入损失。

数值型历史／未来已知协变量按固定角色支持：只有未来已知行使用全窗统计和双向上下文，
官方变量掩码阻止其携带未来目标或历史协变量回流。第二轮发布时尚未支持 DHF 分类协变量、
缺口增强或随机角色采样；这些能力在下述第三轮补充。

验证始终执行普通单起点预测，读取配置的 `context_length` 历史、预测 `prediction_length`，
并按 `validation_loss_space` 选优；不会用随机 DHF 验证替换原有准则。
窗口和布局使用独立、随检查点恢复的随机状态；布局种子取 `seed ^ 0x444846`，
验证不消耗二者。日志记录实际监督点数、按样本计数的预测块及实际截断块长分布。

机制验证包含图 5 手工掩码、目标输入的单块官方推理及多块独立前缀参考、
预测块隔离、上下文不读预测 token、未来信息与跨序列隔离，以及全参数／LoRA 的有限梯度、
精确恢复和导出。未来已知协变量使用全窗统计，不能将裁短已知窗口后的前缀计算声称为相同参考。
实测结果与证据见[第二轮实验](../results/report_round2/README.md)及
[验收报告](../results/report_round2/acceptance.zh-CN.md)。
相同优化步数下，DHF 的监督点数、历史分布和计算量均与窗口训练不同；
此对照评估整套训练策略，不能单独归因于共享编码，也不构成官方预训练复现。

## 第三轮：输入缺口、动态角色与逐起点分类编码

报告 §3.1 强调人工隐藏的读数仍然可以成为监督目标；§3.2 用变量角色改变可用信息。
本轮分别保存原始标签、原始观测掩码、增强后输入掩码和最终监督掩码。
人工缺口只改变输入副本；原始 NaN 永不计分。若缺口抹去某个目标在当前块之前的全部历史，
该目标／块不计分，直到后续起点具有有效历史。

```python
training = TrainConfig(
    mode="lora", training_strategy="dhf", loss_space="normalized",
    validation_loss_space="history_scaled", context_length=256, prediction_length=192,
    missing_probability=.5, missing_max_span=64,
    dynamic_role_sampling=True, role_probabilities=[.5, .25, .25],
)
```

`missing_probability=0` 和 `dynamic_role_sampling=False` 保留原行为。
缺口以配置概率选中每个数值行，再均匀选择 1–最大跨度的连续长度与合法起点，最大跨度受序列长度限制。
分类代码不做数值缺口增强。角色采样只作用于原 `target_columns`：目标／历史／未来已知的默认概率
为 .5/.25/.25；没有目标时均匀选回一个。固定声明协变量保持原角色，类别变量不参与角色采样。
角色按样本固定，同一样本的全部 DHF 块共用；本次非目标变量只提供输入、不承担监督。
角色选择通过官方时间／变量注意力和归一化进入模型，不添加角色嵌入。
这些采样分布属于项目选择，报告未公开具体配方。

DHF 数值路径仍共享一次 Transformer 前向，未来已知行沿用全窗口归一化与双向上下文。
带分类协变量时使用逐样本、逐起点参考路径：每块重新用该起点的目标历史编码类别，
历史协变量截断在起点，未来已知协变量截断在该块末尾，与公开单起点 API 的信息范围一致。
类别代码在编码前保持 CPU float64。固定上游仅在当前样本恰好一个目标时做目标编码，
多目标沿用数值类别代码；角色采样可能改变该分支。表格处理使用仅在训练集建立的紧凑词表，
外部任意大类别代码在多目标 FP32 回退路径不保证身份无损。此路径不共享编码，不能宣称拥有数值路径的加速；
其模型参数可训练，但离散类别预处理不支持类别代码／编码目标输入梯度。

窗口抽样、DHF 布局、缺口和角色采样有独立随机状态并随检查点精确恢复。
缺口与角色种子分别取 `seed ^ 0x4D495353`、`seed ^ 0x524F4C45`；验证不消耗增强随机流。
训练日志记录原始／输入观测点、人工隐藏点、隐藏但计分点、各角色行数与实际监督点数。
全参数／LoRA、窗口／DHF、旧配置默认值和合并／适配器导出都有对应验收。

完整实验协议见[第三轮示例](../examples/report_round3/README.md)，结果见
[第三轮实验记录](../results/report_round3/README.md)。四组消融共享 DHF 配置，以完整和固定缺口历史评估。
角色采样减少了监督目标数量，也改变了预测所条件化的信息；相同步数并不等于等监督量或等计算量。
短期 ETT 适配用于检验实现与观察取舍，不是官方预训练复现。

## 第四轮：合成先验与分阶段继续训练

报告§4.1先以8192长度纯合成预训练，再以32768长度真实/合成后训练；完整生成器、概率分布和比例未公开。
本项目新增可序列化的`SyntheticConfig`与`TrainingStage`，明确作为社区选择的继续训练机制。
生成包含线性/二次趋势、周期谐波、AR(1)噪声、水平/斜率变化、局部事件、Poisson计数及滞后线性/非线性依赖。
依赖使用固定尺度，不以未来父变量的全窗统计改变早期驱动。

来源选择和生成分别使用`seed ^ 0x4D495854`与`seed ^ 0x53594E54`的CPU Torch随机流，
与窗口、布局、缺口、角色及dropout状态分离。每样本抽来源，训练日志保存实际来源/监督曝光；
checkpoint保存全部流、累计曝光和阶段位置。阶段只切训练上下文和来源比例，验证历史保持顶层配置固定。
优化器和学习率计划连续。纯合成阶段无需同长度真实窗口，仍保存全训练表身份。

出现正合成概率时暂只支持声明目标schema；固定数值/分类协变量会明确拒绝，纯真实阶段继续支持。
这项边界不限制原目标动态角色和缺口机制。训练不使用验证/测试标签生成序列或抽窗口。
默认配置不创建合成流，保留旧行为；Python与YAML嵌套配置均可保存/恢复。

正式对照三组共享C128→C256日程和总预算，真实、混合、先合成后混合仅来源比例不同。
仅ETTh1训练/验证选优，九个权重全部冻结后评估ETTh1及ETTh2；ETTh2训练段只用于固定标准化和MASE分母。
相同监督量仍包含不同分布的样本，不能把结果单独归因于阶段次序。
[示例与协议](../examples/report_round4/README.md)、[实测与容量记录](../results/report_round4/README.md)
区分短上下文效果与8192/32768单批前后向；两者均不是官方预训练或长上下文质量复现。

## 第五轮：可观测的推理运行配置

报告§4.3讨论低精度与编译后的推理效率。本项目新增独立 `InferenceConfig`／
`InferenceRuntime`，默认 FP32 eager，提供可选 BF16、编译与按输入签名预热。
只对 Transformer／预测头核心做 autocast／fullgraph Inductor，patch 投影、残差与分位数
重构保留原精度；归一化和推进统计仍为内部 FP64／帧 FP32，MPS 的 FP64 在 CPU。
不转换权重 dtype，也不把编译模块写进原模型结构或导出。

真实编译执行计数与请求／实际模式分开记录，默认失败抛错；显式回退记录原因、
各成功模式调用数及是否混合执行。高层缓存复用预热实例，运行选项独立序列化，旧模型无需新增字段。
性能以本机固定5M的B1、C256/2048、H96、V1/7、CPU/MPS四运行模式矩阵为依据，
区分加载、运行配置创建、首次、预热与稳定耗时；不借用报告硬件速度。

六项完整GIFT固定split只比较官方5M的CPU FP32与事先固定BF16 eager，属于确定性
运行精度对照，不训练、不挑其他轮权重、不声称完整排行榜或跨模型泛化。
28M/123M/209M另做CPU/MPS、full/LoRA短形状前后向更新、两精度预测与官方导出检查。
范围及负结果见[第五轮实测](../results/report_round5/README.md)和
[运行示例](../examples/report_round5/README.md)；较大模型的编译、长形状质量与CUDA不在本轮实测范围。

## 已有网络能力的边界

patch 大小、RMSNorm／SwiGLU、时间／变量注意力、角色掩码、因果归一化和单调分位数头
均由官方网络提供，前三轮没有替换这些结构。对称平均和非负处理属于推理设置，不计入训练损失。
超过单块的长预测已经由官方分块推理支持；DHF 中各块独立读取真实历史，
与推理时将前块预测中位数回填为后块上下文不同。

官方未公开的合成数据混合比例、块长分布、预训练步数及优化器超参数，不填入推测值冒充官方设置。
